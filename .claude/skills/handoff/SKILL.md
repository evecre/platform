# /handoff — 作業の終え方

返答も記録もすべて日本語で書く。

## 1. やったことを集める

- この会話でやったこと（依頼・変えたこと・決めたこと・確かめたこと）
- `docs/HANDOFF.md` のいちばん上の記録の日付と題（そこから後が今回の分）
- git：

```
git branch --show-current
git status --short
git log --oneline -15
git diff --stat              # commit していない変更
```

- 前回の記録より後の commit で、まだ記録に書かれていないものを拾う
- 引数（$ARGUMENTS）があれば、その内容を必ず記録に入れる

## 2. docs/HANDOFF.md に記録を足す

- **一番上**（`---` の直後、いちばん新しい記録の前）に足す。古い記録は書き換えない
- 同じ日・同じ題の記録がすでに一番上にあり、その続きの作業なら、新しく足さずにその記録へ追記する
- 形はファイルの「テンプレート」に合わせる。書くことが無い行は「なし」：

```
## YYYY-MM-DD — <やったことの短い題>
- 依頼：（ユーザーの言葉を短く）
- やったこと：
- 変えたファイル：
- 決めたこと・理由：
- 確かめたこと（コマンドと結果）：
- 残っていること・次にやること：（main へのマージ待ちなら書く）
- ユーザーに確認したいこと：
- 本体側に頼むこと：
```

- 日付は今日の日付。次のセッションが**一番上だけ読めば続きができる**ように書く（ファイル名・変数名・値は具体的に）
- 確かめていないことを「確かめた」と書かない

## 3. ほかの文書を直す（必要なときだけ）

- `CLAUDE.md`：新しい決まり・仕組み・ユーザーの決定があれば、該当する節（§4 CSS、§7 展示モード、§15 Top など）に追記する
- `docs/START.md`：指示書の状態（「指示書の一覧と状態」の表）や、動かし方・確認コマンドが変わったら直す
- `assets/css/README.md`：CSS の調整の仕方が変わったら直す

## 4. 報告する

- 足した記録の題と、直した文書の一覧を短く報告する
- **commit はしない**（ユーザーに頼まれたら、feature ブランチで commit → `git push origin HEAD`。`git push origin main` は使わない。`docs/evecre-web.pdf`・`docs/05_move-archive.md` は commit しない）
