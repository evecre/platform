## 2. 詳細設定の中身（本体のいまの動き。ここが正）

### 2-1. どこにあるか・誰が使えるか

- タスクの作成シート（メインボードの右下の [icon:home-plus]）、または既存のタスクの編集シートの上の「基本設定｜詳細設定」で「詳細設定」を選ぶ
- タスクを作る・直すのは**管理者だけ**。詳細設定も管理者だけが触れる
- 詳細設定の画面には、上から次の5つが並ぶ。既存のタスクを編集しているときは、いちばん下に「このタスクを削除する」も出る

| 画面の名前 | 種類 | 画面に出る説明（そのまま） |
|---|---|---|
| チェック項目 | 項目を足す（「チェック項目を追加」「+ 追加」） | 担当者にチェックしてもらいたい項目を設定できます。 |
| 全員にアナウンスする | オン／オフ | メインボードにてアナウンスされます。 |
| ワンタップで完了する | オン／オフ | テキスト・完了ボタンのみで即完了するようになります。 |
| 個別で完了する | オン／オフ | ユーザーごとに個別に回答・完了できるようになります。 |
| 担当者を応募する | オン／オフ（オンにすると「応募期限（任意）」が出る） | 担当したいメンバーが応募し、管理者が担当者を選定することができるようになります。 |

★5つとも**同時にオンにできる**（片方をオンにすると片方が切れる、ということは無い）。ただし「担当者を応募する」をオンにすると、基本設定の担当者の欄は空になり「応募型：メンバーが自分で割り当てます」と出て選べなくなる。

### 2-2. チェック項目

- 管理者が「〇〇はできているか」のような確認の項目を並べる。1行に1つ。× で消せる
- 担当者がタスクの詳細を開くと、完了の入力欄の上に「チェック項目」として並ぶ
- **全部にチェックを入れないと完了できない。** 残っていると完了ボタンを押してもエラーが出て止まる
- 例：「会場の予約番号を控えたか」「請求書を受け取ったか」

### 2-3. 全員にアナウンスする

- オンにすると、そのタスクが**メインボードの上のお知らせのカード**に出る。タップでタスクの詳細へ
- 出る相手：**担当者がいないタスクならメンバー全員**。担当者がいれば、その担当者（ロールで指定したときはそのロールを持つ人）だけ
- 完了したら、カードは消える
- お知らせが複数あるときはタイトルだけが並ぶ（1件のときは説明も出る）
- 例：「全員、当日の集合時間を確認する」

### 2-4. ワンタップで完了する

- オンにすると、タスクの詳細には「完了する」のボタンだけが出る（文章・画像・PDF の入力欄が無い）
- 押せばすぐ完了。**完了したあとの振り返り（うまくいった／つまずいた）も聞かない**
- 例：「名札を受け取る」「アンケートに答えた」のように、報告する中身が要らない作業

### 2-5. 個別で完了する

- オンにすると、1つのタスクを**一人ずつ**完了する。タスクの詳細には「完了状況：2 / 5 人」と、人ごとの「完了済み／未完了」と提出した中身が並ぶ
- 誰が出せるか・いつタスクが完了になるかは、担当者の決め方で変わる：

| 担当者 | 出せる人 | タスク全体が完了になるとき |
|---|---|---|
| 人を選んでいる（1人でも複数でも） | 選ばれた人だけ | **選ばれた人が全員出したとき**（自動） |
| 決めていない／ロールで指定 | メンバーなら誰でも | **自動では完了しない。** 管理者が「公開終了する」を押したとき |

- 管理者には、タスクの詳細の下に「公開終了する」のボタンが出る（未完了のあいだ）
- 「ワンタップで完了する」と一緒にオンにすると、一人ずつ「完了する」を押すだけの出欠のような使い方になる
- アーカイブでは、提出した人ごとに折りたたまれて並ぶ
- 例：「全員、Tシャツのサイズを書く」「各自の担当の進み具合を一言」

### 2-6. 担当者を応募する

- オンにすると、担当者を管理者が決める代わりに、**メンバーが手を挙げ、管理者が選ぶ**
- 「応募期限（任意）」でカレンダーから日付を選べる。期限はその日の **23:59** まで。「期限をクリア」で外せる

流れ：

1. メンバーのメインボードのタスクに「担当者を応募するタスク」の札と「応募する」ボタンが出る。押すと「応募中」になり、「取り消し」で取り消せる。下に「応募 N名・期限 〇/〇」が出る
2. 期限を過ぎると「応募期限終了」になり、応募できない
3. 応募があると、管理者に通知が届き、メインボードの上に「タスクへの応募があります（N件）」が出る。通知タブにも「応募待ち」が並ぶ
4. 管理者が「選定する」（通知タブでは「担当者を選定する」）を押し、応募者の中から**何人でも**選んで確定する。参加時に答えた「できること・やってみたいこと」に合う人には「おすすめ」の札が付く
5. 選ばれた人が担当者になる。メンバー全員に「担当が決まりました」の通知、選ばれた人のスマホには通知（プッシュ）が届く

注意：

- 担当者がまだ決まっていないあいだは、そのタスクを完了できない（タスクの詳細に「応募型タスクです（担当ではありません）」と出る）
- 閲覧のみのロールの人は応募できない（「担当を募集中」とだけ出る）
- 応募が0人のままだと、管理者は選べない。期限を外す・延ばす、か、「担当者を応募する」をオフにして基本設定で担当者を選ぶ

### 2-7. このタスクを削除する

- 既存のタスクを編集しているときだけ、詳細設定のいちばん下に出る（管理者だけ）
- 最初からあるタスク（「このイベントの目的・目標を決めよう」「どんなイベントか、概要を書いてみよう」）は削除できない

## 3. Phase 1：ヘルプに記事を足す

`assets/data/help.json` の `articles` に、`task-create` のすぐ後へ1つ足す。

- `id`: `task-advanced`
- `category`: `task`
- `title`: 「タスクの詳細設定（チェック項目・アナウンス・個別で完了・応募）」の形。長ければ「タスクの詳細設定を使う」でもよい
- `audience`: `["管理者"]`／`devices`: `["all"]`
- `summary`: 最初の2行で答える（例：「タスクの作成シートの『詳細設定』で、完了前のチェック・メインボードでのお知らせ・一人ずつの提出・担当者の応募を決められます。」）
- `keywords`: 詳細設定・チェック項目・チェックリスト・アナウンス・お知らせ・ワンタップ・個別・一人ずつ・応募・募集・立候補・選定・応募期限・公開終了 など
- `body`: §2 を、書き方の決まり（設計案 §2）に沿って並べる。見出しは5つの項目の画面の名前そのまま。各項目は「何が起きるか → 使いどころの例 → 注意」の順。個別で完了の表（§2-5）は、`body` の型に表が無ければ箇条書きにする
- `related`: `task-create`・`task-complete`・`roles`
- `updated`: 書いた日／`checked`: `false`（ユーザーが本体の画面で確かめるまで）

あわせて：

- `task-create` の本文の最後に「詳細設定で、チェック項目・アナウンス・一人ずつの提出・担当者の応募を決められます」という1行と、`related` に `task-advanced` を足す
- `task-complete` に、チェック項目が出るタスクでは全部チェックしないと完了できないこと、ワンタップで完了するタスクでは振り返りを聞かれないことを1行ずつ足す（今の書き方と矛盾していればそちらを直す）

★書かないこと：本体の内部の名前（`selfClaim`・`individualClear`・`noInput`・`announce`・`claimMode`）。画面の言葉だけで書く。

## 4. Phase 2：チャットボット

`assets/data/faq.json` の `items`。`help` は新しい記事 `task-advanced` を指す。

### 4-1. 直す（今ある2つ）

- `claim-recruit` の答え：応募期限（23:59 まで）、管理者が「選定する」で何人でも選べること、決まるまで完了できないことを足す。`help` を `task-advanced` に
- `individual-clear` の答え：「担当者を選んでいれば、その人たちが全員出したら完了。担当者を決めていなければメンバーなら誰でも出せて、管理者が『公開終了する』で締める」を足す。`help` を `task-advanced` に

### 4-2. 足す（例。言い回しは整えてよい。patterns はそれぞれ5つ以上）

| id（例） | 質問 | 答えの芯 |
|---|---|---|
| `task-advanced` | 詳細設定って何ができる？ | 5つの項目を1行ずつ。作成シートの上の「詳細設定」から |
| `checklist` | 完了の前に確認してほしいことがある | 「チェック項目」。全部チェックしないと完了できない |
| `checklist-blocked` | 完了ボタンを押しても完了できない | チェック項目が残っていないか。担当者を応募するタスクで、まだ担当が決まっていないか |
| `announce` | 全員に知らせたいタスクがある | 「全員にアナウンスする」。メインボードの上に出る。担当者がいれば担当者だけ。完了で消える |
| `one-tap` | ボタンだけで終わらせたい・報告が要らない | 「ワンタップで完了する」。振り返りも聞かない |
| `individual-close` | 個別のタスクがいつまでも完了にならない | 担当者を決めていないと自動では完了しない。管理者が「公開終了する」 |
| `claim-apply` | 応募するにはどうする？（メンバー） | メインボードのタスクの「応募する」。取り消せる。期限を過ぎると押せない |
| `claim-select` | 応募してきた人を選ぶには？（管理者） | メインボードの上の「選定する」か通知タブの「担当者を選定する」。何人でも。「おすすめ」の札 |

- `synonyms.json` に言い換えを足す（例：チェック項目 ← チェックリスト・確認項目／アナウンス ← お知らせ・周知・告知／応募 ← 立候補・手を挙げる・募集／個別 ← 一人ずつ・各自・全員分）。★「告知」は公開（宣伝用に公開）の話とぶつかりやすいので、足したら誤答を確かめる
- `faq-tests.json` に、足した Q&A ごとに言い換えの質問を2つ以上足す
