## 2. 画面の切り替えの仕組み

### 2-1. 切り替え方を変える

いまの `scrollStage.js` は「スクロール量に合わせて scene の状態を変える」作り（sticky ＋ `--progress`）。今回は**1回のスクロール操作で1画面ぶん切り替わり、切り替わりのアニメーションは時間で再生する**形にする（紙芝居の構造。スクロール量にアニメーションを連動させない）。

- 入力：ホイール／トラックパッド、タッチのスワイプ、キー（↓ / PageDown / Space で次、↑ / PageUp で前）、現在位置のドット
- 1回の操作で1画面だけ進む・戻る。**切り替えのアニメーション中は次の入力を受け付けない**（トラックパッドの慣性で何画面も飛ばないように）
- 入力を受け付けない時間は JS に数字で書かず、**CSS の変数から読む**（§3。時間の調整を CSS だけで済ませるため）
- Top ではページ自体はスクロールさせない（`overflow: hidden`）。ほかのページには影響させない
- 公開している関数（`goTo` / `next` / `prev` / `current` / `count`）は残し、`autoAdvance.js` から今までどおり呼べるようにする
- JS が動かないときは、今までどおり縦に並んだページとして読めるようにする

### 2-2. 状態の名前

各画面（section）に状態を付け、CSS はそれを見てアニメーションを書く。

| 状態 | 意味 |
|---|---|
| `before` | まだ来ていない（非表示） |
| `entering` | 出現のアニメーション中 |
| `active` | 表示中 |
| `leaving` | 後退のアニメーション中 |
| `after` | 通り過ぎた（非表示） |

- 付け方（`data-state` 属性か `is-` クラスか）は任せる。決めたら `assets/css/README.md` に書く
- 前の画面の `leaving` と次の画面の `entering` は**同時に始めてよい**（画面ごとに §4 で指定がある場合はそれに従う）
- **戻る（上にスクロール）とき**：戻った先の画面は、**進むときと同じ出現のアニメーション**を再生する。去る画面は短いフェードで消す（専用の逆再生は作らない）

### 2-3. 画面をまたいで残る要素

次の2つは、**画面ごとに別々の要素を置かず、1つの要素を動かして**つなぐ。

- **キャラクター**（02 → 03 で、そのまま縮小しながら移動する。03 → 04 でポンッと消える）
- **howtouse のスマホ**（04〜08。出入りせず、位置が滑らかに移り、画面の中身も途切れずに替わる）

画面の上に1枚重ねた層（例：`l-stage__persistent`）に置き、**画面ごとの位置・大きさを CSS の変数で持たせる**（例：`[data-current="03"] { --chara-x: …; --chara-scale: …; }`）。現在の画面を stage の要素に属性で付け、CSS の transition で移る。値の調整が CSS だけで済むようにすること。

★03-about の UI（スマホなど）と、04〜08 のスマホは**別のもの**。03 の UI は 03 の中で出て、03 と一緒に後退する。

## 3. 調整しやすい書き方（いちばん大事）

Usami があとで「速さ・距離・順番・イージング」を直す。**どこを触れば何が変わるか**が一目で分かるようにする。

### 3-1. 値は名前を付けて1か所に

`assets/css/foundation/_variables.css`（または Top 専用の変数ファイル）に、例えば次のような名前で置く。名前・単位は任せる。

```css
:root {
  /* 出現・後退の基本 */
  --motion-duration-enter: 0.8s;
  --motion-duration-leave: 0.6s;
  --motion-stagger: 0.25s;          /* 順番1つぶんの遅れ */
  --motion-ease-enter: cubic-bezier(.2, .8, .2, 1);
  --motion-ease-leave: cubic-bezier(.4, 0, 1, 1);
  --motion-ease-pop: cubic-bezier(.34, 1.56, .64, 1); /* ポンッ */

  /* 距離・大きさ */
  --motion-distance-up: 40px;       /* フェードアップ */
  --motion-distance-slide: 32px;    /* 横からのスライド（landform は短く） */
  --motion-pop-from: 0.6;           /* ポンッの始まりの大きさ */
  --motion-pop-over: 1.08;          /* ポンッで行き過ぎる大きさ */

  /* 画面の切り替え */
  --motion-curtain-duration: 0.9s;  /* hero → 02 の白い幕 */
  --motion-iris-duration: 1.2s;     /* 08 → 09 の円形の出現 */
  --motion-shrink-duration: 0.9s;   /* 09 → 01 の収縮 */
  --motion-bg-duration: 0.8s;       /* 04〜08 の背景色 */
  --motion-bg-ease: ease;

  /* キャラクターの目 */
  --eye-blink-duration: 0.15s;
  --eye-look-duration: 0.4s;
  --eye-look-distance: 4px;         /* 黒目が動く量 */

  /* hero の雲・09 のスライダー */
  --hero-cloud-speed: 60s;          /* 横断にかかる時間（遅め） */
  --slider-speed: 40s;
}
```

★瞬き・視線移動・雲の**間隔**（ランダムの最小〜最大）は JS で決めることになるが、数字は JS に直書きせず CSS の変数から読む（例：`--eye-blink-interval-min: 2s; --eye-blink-interval-max: 6s;`）。

### 3-2. 動きの種類は名前で選ぶ

動きの種類（プリセット）を作り、HTML の属性で選べるようにする。例：

```html
<div data-enter="fade-up" data-order="1" data-leave="fade-up-out" …>
```

| 種類 | 動き |
|---|---|
| `fade-up` | 下から上へフェードアップ |
| `pop` | ポンッと出現：小さい状態（`--motion-pop-from`）から少し大きく行き過ぎて（`--motion-pop-over`）元の大きさに戻る。弾むように |
| `slide-left` | 左横から短くフェードスライドイン |
| `slide-right` | 右横から短くフェードスライドイン |
| `fade-up-out`（後退） | さらに下から上へ動きながら消える |
| `pop-out`（後退） | ポンッと消える：一瞬少し膨らんでから、小さくなって消える |
| `none` | 動かさない（元からある） |

- **順番**：`data-order="n"` の遅れ＝`(n - 1) × --motion-stagger`。順番は指示書の数字をそのまま使う（hero の ipad は「5」なので、2 のあとに間が空くのが意図どおり）
- 要素ごとに距離などを変えたいときは、**その要素の CSS で変数を上書きする**だけで済むようにする（例：landform だけ `--motion-distance-slide` を小さく）
- プリセットは1つのファイルにまとめる（FLOCSS のどこに置くかは任せる。置き場所と使い方を `assets/css/README.md` に書く）
- JS には時間・距離の数字を書かない。必要なら `getComputedStyle` で CSS の変数を読む

### 3-3. 動きを減らす設定

`prefers-reduced-motion: reduce` のときは、移動・拡大縮小をやめてフェードだけにする。雲・スライダー・目の動きは止める。

## 5. 素材と読み込み（エコに）

### 5-1. 使う素材

- `assets/img/top/`：hero のマスク・雲・landform・mizu-phone・キャラクター、ipad・PC・スマホの UI 画像、背景（`planning` / `writing` / `mountaineering` / `summit` など）
- `assets/img/character/`：キャラクターの本体・白目・黒目（§6）
- どの素材をどの画面で使うかは Figma で確かめ、Phase 0 で一覧にして報告する。**足りない素材は勝手に作らず報告する**

### 5-2. 形式と大きさを出し分ける

素材によって、ある形式・大きさが違う（例：UI の画像は `avif` / `webp` / `png`、ipad は `avif` / `png`、背景と landform は `-768w`〜`-5120w` の `webp`）。**フォルダにあるものだけを使って**、ブラウザが必要最小限のものを選べるようにする。

- **形式**：`<picture>` の `<source type="image/avif">` → `<source type="image/webp">` → `<img>`（png）の順に並べる。ある形式だけを書く
- **大きさ**：幅違いがある素材は `srcset` に `768w` 〜 `5120w` を並べ、`sizes` をその画像の**実際の表示幅**に合わせて書く（画面いっぱいなら `100vw`、半分なら `50vw` など）。`sizes` を省いて大きすぎる画像を読ませないこと
- 1つの大きさしかない素材は `srcset` を使わなくてよい
- `<img>` には `width` / `height`（元の比率）を書き、読み込み中にレイアウトがずれないようにする
- **SVG**（マスク・雲・キャラクター・mizu-phone・role など）はそのまま使う。キャラクターは §6 のとおりページに直接書き込む
- 読み込みの優先度：
  - 01-hero の画像は `fetchpriority="high"`、遅延読み込みしない
  - それ以外は、**次の画面に進む前に読み込みを始めておく**（切り替えの瞬間に画像が無くて出現アニメーションが空振りしないように）。最初から全部を読まないこと
- 足りない形式・大きさがあっても、変換して作らない。**どの素材に何が足りないかを報告する**（Usami が書き出す）

## 6. キャラクターの目（01〜03）

- **デフォルトの目の位置は Figma の画像の位置**。ずれないことをいちばん大事にする
- 素材：`assets/img/character/` に、キャラクターごとの本体（`character-*-body.svg`）・黒目（`character-*-iris.svg`）と、白目（`character-eye.svg`）がある。hero は `assets/img/top/hero-charcters.svg`（3体がまとまった1枚）
  - 目を動かすには目の部分を個別に動かせる必要があるので、**SVG をページに直接書き込む**（`<img>` では中を動かせない）。部品の SVG を重ねるか、まとまった SVG の中の目の要素を使うかは、Figma と合うほうを選んで報告する
  - ★Illustrator から書き出した SVG は、どれも同じ `id`（`_レイヤー_2` など）と同じ class（`.cls-1` など）を持っていて、`<style>` も入っている。**同じページに複数書き込むと、id が重複し、色の指定が別の SVG に当たって色が変わる。** 書き込むときに、id は消すか重ならない名前にし、`<style>` の色は属性（`fill`）に移すなど、互いに干渉しないようにすること
- **瞬き**：白目と黒目をまとめて、上下に一瞬縮めて戻す。間隔はランダム（ときどき2回続けてもよい）
- **視線移動**：黒目を白目の中で少しだけ動かし、しばらくしてデフォルトの位置に戻る。方向・間隔はランダム。黒目が白目からはみ出さないこと
- 3体がいる画面では、3体が**同時にそろって**動かないようにする（それぞれ別のタイミング）
- 画面に見えていないキャラクターは動かさない
- 時間・量は §3-1 の変数で調整できるようにする

## 7. ヘッダー

- 項目は **TOP / みんなの記録 / ヘルプ**
  - TOP：`/`
  - みんなの記録：本体の `/explore`（`EXPLORE_URL`）
  - ヘルプ：`/pages/help/`
- Top 以外のページ（ヘルプなど）でも同じヘッダーにする
- 見た目・置き方は Figma に合わせる。hero の上に重なるなら、各画面の要素と重ならないこと

## 8. レイアウト

- 基準は Figma のフレームのサイズ。画面の大きさに合わせて**全体を拡大縮小**する作り（`vw` / `svh` を基準にする等）にし、1280px〜3840px の横幅で同じ構図を保つ
- 位置は Figma と完全に同じでなくてよい
- **スマホ（縦長の画面）の見せ方は任せる。** Figma に無いので、構図を縦に組み替えてよい。決めた見せ方を報告する
- 現在位置のドット・ヘッダー・チャットボットのボタンが、各画面の要素と重ならないこと

## 10. 確認

```
npm run check
node scripts/serve.mjs                 # http://localhost:5173
node scripts/serve.mjs --kiosk         # 展示モード（?kiosk=1&fast=1 で速く確認）
npm run build && node scripts/serve.mjs --root dist
```

**手で確かめること**

- ホイール・トラックパッド・キー・ドット・スワイプで、1回に1画面ずつ切り替わる。慣性で飛ばない
- 各画面の出現・後退が指定の順番で起きる
- 02 → 03 でキャラクターが1つのまま縮小・移動し、03 → 04 でポンッと消える
- 04〜08 でスマホが1つのまま移り、中身が途切れずに替わる。背景色がなめらかに替わる
- 08 → 09 で、08 がそのままの位置で、中央から広がる円に覆われる
- hero の雲がマスクの中だけに見え、右の外から出て左へ流れる。hero-mizu-phone はマスクの上に出ている
- キャラクターの目が Figma の位置にあり、ランダムに瞬き・視線移動する。3体がそろって動かない。色が他の SVG に引っぱられていない
- 09 のスライダーが上下で逆向きに途切れず流れる。「みんなの記録」で本体の `/explore` が開く
- 09 から下へスクロールしても進まない
- 展示モード：30秒ごとに進み、09 の次は中央へ収縮して 01 に戻り、ループする。操作で止まり、再開する。チャットボットを開くと止まる
- `prefers-reduced-motion` で動きが減る
- **DevTools の Network で、画面の幅に合った大きさ・avif（または webp）が読まれている**。1280px の画面で `-5120w` が読まれていない。Top を開いた瞬間に全画面の画像を読んでいない
- 375px・1280px・1920×1080・3840×2160 で構図が崩れない
- コンソールにエラーが無い
