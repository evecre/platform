# 外部サイトへの連絡：公開 API の詳細に「目的」と「柱」を足しました

> 送り先：イベクリの外部サイトを開発している Claude Code
> 送り元：イベクリ本体（main `26e8c62`。2026-11-09 にマージ）

## 1. 何が変わったか

`GET /api/public/events/:id`（詳細）の応答に、2つの項目を足しました。**今ある項目の形・値は変えていません。**

```json
{
  "ok": true,
  "id": "1787536757139",
  "status": "archive",
  "basic": { "title": "…", "summary": "…", "…": "…" },
  "purpose": "地域の子どもが、ひとりで来ても居場所があると感じられる祭りにする",
  "pillars": ["孤立させない", "地域とつながる"],
  "knowledge": [ … ]
}
```

| 項目 | 型 | 中身 |
|---|---|---|
| `purpose` | `string \| null` | イベントの**目的**（なぜやるのか）。本体の初期タスク「このイベントの目的・目標を決めよう」に書かれた文章。文字だけで、書式の印は含まない |
| `pillars` | `string[] \| null` | 目的を支える**柱**（何を大事にするか）。名前だけ、最大3つ、本体で決めた順 |

## 2. いつ値が入るか

どちらも、**タスクの記録（`knowledge`）が1件以上公開されているときだけ**値が入ります。本体のアーカイブで、目的をタスクの記録の先頭に並べているためです。

| 状況 | `purpose` | `pillars` |
|---|---|---|
| `knowledge` が1件以上 ＋ 目的が書かれている | 文字列 | 柱の名前の配列（柱が無ければ `[]`） |
| `knowledge` が1件以上 ＋ 目的がまだ書かれていない | `null` | 同上 |
| `knowledge` が `null` または `[]`（開催前・記録を公開していない） | `null` | `null` |

- 開催前の宣伝の段階（基礎情報だけ公開）では、どちらも `null` です。
- 柱の id・目的を書いた人・書いた時刻は出しません。

## 3. 変えていないもの

- `GET /api/public/events`（一覧）：変更なし。`purpose` / `pillars` は入りません。
- `GET /api/public/reflections`：変更なし。目的は振り返りではないので、`items` に入りません。
- `knowledge[]`：変更なし。目的は `knowledge[]` の1件としては返しません（`outcome` などを持たないため）。

## 4. 外部サイトでお願いしたいこと

- `docs/api-contract.md` の詳細の節に、上の2項目と「いつ値が入るか」の表を足してください。
- 詳細ページでは、タスクの記録の前に「目的」と「柱」を出すのがおすすめです。本体のアーカイブと同じ並びです。
  - `purpose` が `null` なら目的の見出しごと出さない
  - `pillars` が `null` か `[]` なら柱の見出しごと出さない
- 項目が無い（古い snapshot など）ときも `null` と同じに扱ってください。

## 5. 参考：本体側のそのほかの変更（API には影響なし）

- 本体のアーカイブの「完了日順」を古い順にしました。API の `knowledge[]` の並びは変わっていません。
- 本体の初期タスク「企画をざっくり書いてみよう」の名前を「どんなイベントか、概要を書いてみよう」に変えました。`summary`（概要）は、これまでどおりこのタスクに書かれた内容です。

## 6. 確認

- 本体の `npm run check:public`：101件 OK（目的・柱の条件、id を出さないこと、reflections に入らないことを含む）
- 本番で値が入るのは、Render へのデプロイが済み、かつ記録を公開しているイベントがあるときです。2026-11-09 時点で、本番に記録を公開しているイベントは0件です。
