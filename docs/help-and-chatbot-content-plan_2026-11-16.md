# 外部サイトのヘルプページとチャットボットに載せる内容（設計案）

> 作成：2026-11-16（本体 main の状態をもとに書いています）
> 読む人：イベクリの外部サイト（https://evecre.pages.dev/）のヘルプページとチャットボットを作る人（運営者・外部サイト担当の Claude Code）
> 関連：機能の一覧と実装日は `docs/feature-inventory_2026-11-16.md`

この資料は「何を書けばよいか」をまとめたものです。各ページの本文そのものではありません。
ただ、チャットボットにそのまま渡せるよう、§6 の Q&A は答えの文まで書いています。

---

## 0. 結論（先に決めたいこと3つ）

1. **ヘルプとチャットボットの中身は同じ文章にする。** ヘルプの1ページを「1つの話題」に絞り、その文章をそのままチャットボットの知識として読ませます。2か所に別々に書くと、片方だけ古くなるためです。
2. **書き手の目線ではなく、使う人のやりたいことから書く。** 機能の名前（例：「柱」「アーカイブ」）で分けるのではなく、「メンバーを招待したい」「通知が届かない」のように書きます。機能の名前は、ページの中で説明します。
3. **立場（管理者かメンバーか）と端末（iPhone・Android・PC）を、どのページにも書く。** イベクリは、管理者にしか出ないボタンや、iPhone だけ手順が違う場面が多いからです。チャットボットへの質問の多くは「ボタンが見つからない」になると見込んでいます。

## 1. 前提

### 1-1. ヘルプとチャットボットの役割

| | ヘルプページ | チャットボット |
|---|---|---|
| 向いていること | 手順を順番に読む・画面を見ながら進める | 「〇〇できない」「〇〇はどこ？」にすぐ答える |
| 中身 | 1ページ＝1つの話題（手順・注意・関連ページ） | ヘルプのページを小さく分けたもの＋§6 の Q&A |
| 答えられないとき | 問い合わせ先へのリンク | 答えを作らず、ヘルプのページか問い合わせ先へ案内する |

### 1-2. 正しい情報の元

- ヘルプの内容は**本体のいまの挙動**が正です。本体の CLAUDE.md と画面を元に書いてください。
- 本体で機能を変えたら、§11 の表で直すページを確かめます。
- 文章の中の数字（上限・時刻・日数）は、§12 の表にまとめました。チャットボットにはこの表も渡します。

### 1-3. 用語をそろえる

アプリの中の言い方に合わせます。古い言い方や社内の言い方は使いません。

| 使う | 使わない | メモ |
|---|---|---|
| タスク／やること | ミッション | 2026-09-16 に改称。★プライバシーポリシーと利用規約にはまだ「ミッション」が残っています（§10） |
| 管理者 | リーダー（権限の意味で） | 「リーダーの意気込み」は画面の言葉なので使ってよい |
| メンバー | 一般ユーザー | 権限を説明するときだけ「一般ユーザー」 |
| プロジェクト | フォルダ | 画面では「プロジェクト」 |
| メインボード | ボード・ホーム画面 | 「ホーム」はイベント一覧のこと |
| 宣伝用に公開／タスクも含めて公開 | 基本情報の公開・ナレッジの公開 | 画面の言葉どおり |
| みんなの記録 | explore・公開ページ | URL は `/explore` |

## 2. 書き方の決まり

1. **1ページ＝1つの「やりたいこと」。** 見出しは問いか動詞で書きます（例：「メンバーを招待する」「通知が届かないとき」）。
2. **最初の2行で答えを言う。** そのあとに手順、最後に注意を書きます。チャットボットは冒頭を引用することが多いので、ここに結論を置きます。
3. **手順は番号つき。1行に1操作。** ボタンの名前は画面の文字どおりに「」で囲みます。
4. **「誰ができるか」を先頭に書く。** 例：「★管理者だけ」「メンバー全員」。
5. **端末で違うところは、端末ごとに分けて書く。** 例：iPhone／Android／PC（ブラウザ）。
6. **数字ははっきり書く。** 「たくさん」ではなく「5枚まで」と書きます。
7. **できないことも書く。** 例：「削除したイベントは元に戻せません」。チャットボットが「できます」と勘違いで答えるのを防ぎます。
8. **画面の場所は、上から順にたどれる形で書く。** 例：「イベントを開く → 右上の設定（歯車）→『メンバー管理』」。
9. 画像を使うときは、**スマホの画面とPCの画面の両方**を用意します。メインボードは、スマホとPCで並びが大きく違います。

## 3. 用語集（ヘルプの1ページ＋チャットボットの言い換えの辞書）

チャットボットには「よく使われる別の言い方」も一緒に渡します。質問の言い換えを拾えるようにするためです。

| 用語 | 説明（ヘルプに載せる文） | 別の言い方（チャットボット用） |
|---|---|---|
| イベント | イベクリで準備する1つの催し。チームはイベントごとに作ります。 | 企画、催し、プロジェクト（※別の意味もある） |
| プロジェクト | 複数のイベントをまとめる箱。班ごとにイベントを分けたときに使います。 | フォルダ、まとめ、グループ |
| メインボード | イベントを開いたときの最初の画面。山と、やることの一覧があります。 | ボード、トップ、イベントのページ |
| タスク（やること） | イベントのために誰かがやる作業。担当者と実施期間を決められます。 | ミッション、ToDo、作業、仕事 |
| ラベル | タスクの種類。企画・運営・制作・広報の4つと、自分で作るタグ。 | タグ、カテゴリ、分類 |
| 担当者 | そのタスクをやる人。複数人でも、ロールでも指定できます。 | 担当、アサイン、割り当て |
| 完了 | タスクが終わったことを知らせること。文章・画像・PDF・リンクを添えて出します。 | クリア、提出、終わらせる、報告 |
| 振り返り | 完了したあとに「うまくいった／つまずいた」と、その理由を書くこと。 | 反省、ふりかえり、感想 |
| 目的 | このイベントを何のためにやるか。最初のタスクで書きます。 | ゴール、目標、狙い |
| 概要 | どんなイベントか。最初のタスクで書きます。アーカイブや招待ページにも出ます。 | 説明、紹介文、イベントの説明 |
| 柱 | 目的を支える「大事にすること」。最大3つ。タスクを柱に紐づけると、どの柱が手薄か見えます。 | 方針、テーマ、軸、ピラー |
| 提案 | イベクリがイベントに合わせて出す、次にやるとよいタスクの案。3つ。 | AI提案、おすすめ、キャラの提案 |
| アーカイブ | 完了したタスクの記録を1本の文書にまとめたもの。 | 記録、まとめ、報告書 |
| みんなの記録 | 公開されたイベントを誰でも見られるページ。 | 公開ページ、explore、事例 |
| 引き継ぎ | 前の代（去年など）のイベントの記録とタスクを、次のイベントに持ってくること。 | 前年度、前の代、継承 |
| ロール | メンバーの役割。管理者権限があるか・閲覧のみか、を決めます。 | 役割、権限、役職 |
| 招待リンク | イベントに人を呼ぶリンク。7日間使えます。 | 招待URL、参加リンク |
| 招待コード | 招待リンクの代わりに、ホームの「イベントに参加」で入力する文字列。 | コード、参加コード |
| フェーズ | イベントの段階。企画準備 → 振り返り → 完了。 | 段階、状態、ステータス |
| 引き継ぎ日 | 振り返りをする日。過ぎると自動で「完了」に進みます。 | 振り返り日 |

## 4. ヘルプの構成（カテゴリとページ）

★印は「最初に作るページ」（問い合わせが多いと見込むもの）。全部で51ページ、うち★は18ページです。

### A. はじめに（5）
| ページ | 誰向け | 入れる要点 |
|---|---|---|
| ★A1 イベクリでできること | 全員 | 3行で：仲間とイベントを準備する／目的を見失わない／記録を次の代に残す。主な画面（ホーム・メインボード・アーカイブ）の役割 |
| ★A2 アカウントを作る | 初めての人 | Google かメールか。メールは確認コードが届く。表示名・アバター・アンケートは途中でやめても続きから。13歳未満は使えない |
| A3 ホーム画面に追加する（アプリのように使う） | スマホ | iPhone は Safari の共有ボタン →「ホーム画面に追加」。Android は案内の「ホームに追加する」かブラウザのメニュー。★iPhone は追加しないと通知が届かない |
| A4 画面の見方（スマホ／PC） | 全員 | スマホは下のボトムナビ（メインボード・アーカイブ・通知）。PC は左端の列。PC はメインボードが左に山・右にカレンダーとやること |
| A5 用語集 | 全員 | §3 の表 |

### B. イベントを作る・整える（7）
| ページ | 誰向け | 入れる要点 |
|---|---|---|
| ★B1 イベントを作る | 作る人 | ホームの「イベントを作成」。8つの画面（名前・種別・来てほしい人数・開催日・意気込み・Discord／Slack 連携・前の代・招待）。開催日・意気込みは「あとで」でよい。作った人がオーナー |
| ★B2 最初にやること（概要・目的・柱） | 作った人 | 最初に「概要」と「目的」の2つのタスクが入っている。書き終えるまでほかの画面へ進めない（オーナーだけ）。そのあと柱を立てる（任意） |
| B3 開催日と時刻を変える | 管理者 | イベント設定の「開催日時」、または日付チップ → カレンダーの「開催日を編集」。時刻を1つ入れると、空いている日にも同じ時刻が入る |
| B4 イベント設定でできること | 全員／管理者 | プロフィール設定・イベント管理・メンバー管理の3つ。管理者でないと変えられない項目がある |
| B5 フェーズと引き継ぎ日 | 管理者 | 企画準備 → 振り返り → 完了。引き継ぎ日を過ぎると自動で完了。完了にすると提案や催促が止まる |
| B6 プロジェクトでイベントをまとめる | 全員 | ホームのプロジェクトのタブ「＋新規作成」。イベントを長押し →「プロジェクトに追加」。プロジェクトの中で「＋イベント」 |
| B7 イベントを削除する・抜ける | オーナー／メンバー | 削除：オーナーがホームでイベントを長押し →「削除」。元に戻せない。提出物・チャット・通知も消える。抜ける：イベント設定のいちばん下「イベントから脱退する」 |

### C. メンバー（7）
| ページ | 誰向け | 入れる要点 |
|---|---|---|
| ★C1 メンバーを招待する | 管理者 | 招待リンクを送る（7日有効）。相手は申請 → 管理者が承認して参加。承認のときに役割を選ぶ |
| ★C2 招待されたイベントに参加する | 招待された人 | リンクを開く → ログイン／登録 → 参加申請フォーム（できること・やってみたいこと・ひとこと。どれも任意）→ 承認を待つ。コードならホームの「イベントに参加」 |
| ★C3 参加申請を承認する | 管理者 | 通知・お知らせから「承認待ち」を開く。役割を選んで承認。断るとフォームの回答も消える |
| C4 役割（ロール）と権限 | 管理者 | オーナー・管理者・メンバーと、自分で作る役割。「管理者権限」か「一般ユーザー」か。「閲覧のみ」は見るだけ。両方あれば管理者権限が優先 |
| C5 自分のプロフィール（できること・やってみたいこと）を直す | メンバー | イベント設定の「プロフィール設定」。担当者のおすすめに使われる |
| C6 リーダーの意気込みと🔥 | 全員 | 参加したとき、リーダーの意気込みが出る。🔥で応援できる |
| C7 メンバーを外す | 管理者 | イベント設定のメンバー管理から |

### D. タスク（10）
| ページ | 誰向け | 入れる要点 |
|---|---|---|
| ★D1 タスクを作る | 管理者 | メインボードの右下の＋。タスク名・説明・ラベル・優先度・担当者・実施期間。空の項目があれば確認が出る（そのまま作れる）。柱があるときは「次へ」で柱を選ぶ |
| ★D2 タスクを完了する | 担当者 | タスクをタップ → 内容を書く（文章・画像・PDF）→「完了」→ 振り返りのページ →「保存して完了する」か「振り返らずに完了する」。★振り返りのページで戻ると、まだ完了になっていない |
| D3 画像・PDF を付ける | 担当者 | 画像5枚まで、PDF 3つまで（1つ10MB）。文章の途中に置ける。ドラッグ・貼り付け・並べ替え。iPhone の HEIC はブラウザによって入らない |
| D4 文字の書式（太字・見出しなど） | 全員 | 太字・斜体・見出し・箇条書き・非公開。⌘B / ⌘I。非公開にした文字は公開されない |
| D5 担当者を決める・応募してもらう | 管理者 | 担当者のシートでおすすめが出る。なぞって続けて選べる。「担当者を応募する」をオンにすると、メンバーが応募 → 管理者が選ぶ |
| D6 詳細設定（チェック項目・アナウンス・ワンタップで完了・個別で完了） | 管理者 | それぞれの意味と使いどころ |
| D7 タスクを直す・削除する・未完了に戻す | 管理者 | ⋯ のメニュー。★最初の2つのタスク（目的・概要）は名前の変更・削除ができない（中身は直せる）。未完了に戻すと提出物と振り返りも消える |
| D8 タスクのチャット | 全員 | タスク詳細の下。長押しでコピー・返信・削除。リアクション |
| D9 並び替え・絞り込み | 全員 | 締切順（月の見出し）・優先度順・作成日順。「私の／みんなの」。ラベルで絞る |
| D10 タスクのリンクを送る | 全員 | ⋯ の「リンクをコピー」。メンバーでない人は開けない |

### E. 目的・柱・提案（4）
| ページ | 誰向け | 入れる要点 |
|---|---|---|
| ★E1 柱とは | 全員 | 目的を支える「大事にすること」。最大3つ。候補は 運営・進行／制作／企画 に分かれ、区分でキャラが決まる。タスクを紐づけると、柱ごとの件数と進み具合がメインボードの上に出る。0件の柱＝手がついていない |
| E2 柱を立てる・タスクを振り分ける | 管理者 | 目的のボックスの「柱を立てる」かイベント設定。保存すると、未分類のタスクを振り分けるページが出る（「あとで」可） |
| ★E3 キャラクターの提案 | 管理者 | 下の3体が、イベントに合わせて次にやることを3つ出す。タップで作成シートが開く（そのまま作るか直す）。12時間ごとに入れ替わる（開いたときに更新）。開催後・完了したイベントでは出ない |
| E4 目的のリマインド | 全員 | ときどき目的を思い出す画面が出る理由 |

## 5. 各ページを書くときの「つまずき」メモ

本体を作るなかで分かった、利用者がつまずきやすい点です。ページの「注意」に入れてください。

| どこ | つまずき | ヘルプに書くこと |
|---|---|---|
| 参加 | 申請しただけで、すぐには入れない | 「管理者が承認するまで、イベントの中は見られません」 |
| 参加 | 確認コードを入れずに先へ進んだ | 「あとからアカウント設定で認証できます。認証しなくても申請はできます」 |
| ボタンが無い | 管理者でないと出ないボタンが多い（＋・提案・設定の多く） | 「管理者に役割を変えてもらってください」 |
| 完了 | 振り返りのページで戻ると完了していない | 「完了になるのは『保存して完了する』か『振り返らずに完了する』を押したときです」 |
| 完了 | メンバーは完了したタスクが一覧から消える | 「完了したタスクはアーカイブに移ります」 |
| 最初のタスク | 目的・概要を書くまでほかの画面に行けない（オーナー） | 「書き終えると進めます。あとから直せます」 |
| 提案 | 3体が寝ている | 「次の提案を準備中です。12時間ごとに入れ替わります。開催日を過ぎると出ません」 |
| 通知 | iPhone で許可の画面が出ない | 「ホーム画面に追加して、そのアイコンから開いたときだけ許可できます」 |
| 通知 | 一度「許可しない」を押した | 「端末の設定から許可し直してください」（iPhone・Android・Mac の場所） |
| 公開 | タスクの公開スイッチが出ない | 「開催日を過ぎてから出ます」 |
| 公開 | 個人名が出ないか心配 | 「名前・アバター・チャット・メンバーの回答は公開されません」 |
| 画像 | 画像が入らない | 「HEIC はブラウザによって読めません。JPEG・PNG にしてください」 |
| 古い画面 | アップデートしたのに古い | 「アプリを閉じて開き直すか、ページを読み込み直してください」 |
| つながらない | 「通信できませんでした」 | 「電波を確認して『もう一度試す』。ログアウトされたわけではありません」 |
| ホーム画面のアイコン | 新しいアイコンにならない（iPhone） | 「一度削除して追加し直すと変わります」 |

## 6. チャットボット用 Q&A（答えの文つき）

★形：`Q`＝代表の質問／`言い換え`＝同じ意味の質問の例／`A`＝答え（最初の文で結論）／`関連`＝ヘルプのページ。
★答えは「です・ます」で、2〜5文。手順は番号つき。

### 始め方
- **Q：イベクリって何ができるの？**
  言い換え：どんなアプリ？／何に使う？
  A：仲間と一緒にイベントを準備するためのアプリです。やること（タスク）を作って担当を決め、終わったら記録を残します。目的と「大事にすること（柱）」を決めておくと、準備が偏っていないかが見えます。終わったイベントの記録は、次のイベントに引き継げます。
  関連：A1

- **Q：アプリはどこからダウンロードする？**
  言い換え：App Store にある？／インストール方法
  A：ストアのアプリはありません。ブラウザで開いて使います。スマホではホーム画面に追加すると、アプリのように開けます。iPhone では、ホーム画面に追加しないと通知が届きません。
  関連：A3

### イベント
- **Q：イベントを作るには？**
  A：ホームの「イベントを作成」から作れます。名前・種別・来てほしい人数などを順に答えます。開催日や意気込みはあとで決めてもかまいません。最後に招待リンクが出るので、メンバーに送ってください。
  関連：B1

- **Q：最初の画面から先に進めない**
  言い換え：目的を書かないと進めない／戻れない
  A：イベントを作った人は、最初に「概要」と「目的」を書くまで、ほかの画面へ進めません。イベクリでいちばん大事にしている準備だからです。書いた内容はあとから直せます。
  関連：B2

- **Q：開催日を変えたい**
  A：管理者なら、イベント設定の「開催日時」か、メインボードの日付（あと N 日）→ カレンダーの「開催日を編集」から変えられます。日付ごとに開始・終了の時刻も入れられます。
  関連：B3

- **Q：イベントを消したい**
  A：イベントを作った人（オーナー）だけが削除できます。ホームでイベントを長押しして「削除」を選びます。削除すると、タスク・提出物・チャット・通知もすべて消え、元に戻せません。
  関連：B7

- **Q：イベントから抜けたい**
  A：イベント設定のいちばん下にある「イベントから脱退する」から抜けられます。
  関連：B7

### メンバー
- **Q：メンバーを招待したい**
  言い換え：友達を入れたい／招待URL
  A：管理者は、イベント設定の「メンバー管理」→「メンバーを招待」で招待リンクを出せます。リンクは7日間使えます。リンクを開いた人は参加を申請し、管理者が承認すると参加できます。
  関連：C1

- **Q：招待リンクを開いたのに入れない**
  言い換え：参加できない／承認待ちのまま
  A：参加は、管理者の承認が必要です。申請が届いているかを管理者に確認してもらってください。リンクの期限（7日）が切れている場合は、新しいリンクをもらってください。
  関連：C2・C3

- **Q：招待コードはどこに入れる？**
  A：ホームの「イベントに参加」に入れてください。
  関連：C2

- **Q：管理者にしたい／権限を変えたい**
  A：管理者が、イベント設定の「メンバー管理」で、その人の役割を変えられます。「管理者権限」の付いた役割を持つ人は、タスクの作成や設定の変更ができます。
  関連：C4

- **Q：＋ボタン（タスクを作るボタン）が無い**
  言い換え：タスクを作れない／提案が出ない／設定が変えられない
  A：タスクの作成・提案・多くの設定は、管理者だけが使えます。管理者に役割を変えてもらってください。「閲覧のみ」の役割の人は、見ることだけができます。
  関連：C4

### タスク
- **Q：タスクを完了するには？**
  A：
  1. タスクをタップして詳細を開きます。
  2. やったことを書きます（画像や PDF も付けられます）。
  3. 「完了」を押します。
  4. 振り返りのページで「保存して完了する」か「振り返らずに完了する」を押すと、完了になります。
  関連：D2

- **Q：完了を押したのに完了になっていない**
  A：振り返りのページで「戻る」を押すと、完了になりません。もう一度タスクを開き、振り返りのページの最後のボタンまで進めてください。書いた内容は残っています。
  関連：D2

- **Q：画像は何枚付けられる？**
  A：画像は5枚まで、PDF は3つまで（1つ10MBまで）付けられます。文章の途中に置けて、ドラッグで並べ替えられます。本文は4,000字までです。
  関連：D3

- **Q：完了したタスクが消えた**
  A：完了したタスクはアーカイブに移ります。メインボードの「アーカイブ」から見られます。
  関連：H1

- **Q：完了を取り消したい**
  A：管理者が、アーカイブのそのタスクの ⋯ から「未完了に戻す」を選べます。戻すと、提出した内容と振り返りも消えます。
  関連：D7

- **Q：担当を募集したい**
  A：タスクの詳細設定で「担当者を応募する」をオンにすると、メンバーが応募でき、管理者が担当者を選べます。応募の期限も決められます。
  関連：D5

- **Q：みんなに一人ずつ出してほしい（アンケートなど）**
  A：詳細設定の「個別で完了する」をオンにすると、メンバーそれぞれが提出できます。
  関連：D6

### 目的・柱・提案
- **Q：柱って何？**
  A：目的を支える「大事にすること」です。3つまで決められます。タスクを柱に紐づけると、柱ごとのタスクの数と進み具合がメインボードの上に出ます。0件の柱は、まだ誰も手を付けていないという合図です。
  関連：E1

- **Q：キャラクターの提案はどう使う？**
  言い換え：AI の提案／下にいるキャラ
  A：メインボードの下の3体が、イベントに合わせて「次にやるとよいこと」を出します（管理者だけ）。タップすると作成シートが開くので、そのまま作るか直して作ってください。提案は12時間ごとに入れ替わります。
  関連：E3

- **Q：キャラクターが寝ていて提案が出ない**
  A：次の提案を準備中です。12時間たってからメインボードを開くと、新しい提案が出ます。開催日を過ぎたイベントや「完了」にしたイベントでは、提案は出ません。
  関連：E3

- **Q：提案に送られる情報は？**
  A：提案を作るため、イベント名・説明・タスクの内容・進み具合を、AI のサービス（Cloudflare Workers AI）に送っています。メールアドレスやパスワードは送っていません。
  関連：プライバシーポリシー

### 通知
- **Q：通知をオンにしたい**
  A：
  - iPhone：Safari で開き、共有ボタン →「ホーム画面に追加」。追加したアイコンから開くと、通知を許可する画面が出ます。
  - Android・PC：案内が出たら「許可」を押します。
  アカウント設定から、テスト通知を送って確かめられます。
  関連：G1

- **Q：通知が届かない**
  A：§7 の順に確かめてください。いちばん多いのは、iPhone でホーム画面に追加していない場合と、端末の設定で通知が止まっている場合です。
  関連：G3

- **Q：どんなときに通知が来る？**
  A：タスクを割り当てられたとき、新しいタスクができたとき、締め切りの日の朝9時と前日の13時（担当者だけ）などです。くわしくは「届く通知の種類と時刻」を見てください。
  関連：G2

- **Q：Discord に流したい**
  A：管理者は、イベント設定の「外部連携」に Discord か Slack の Webhook の URL を貼ると、タスクの作成・完了と、毎朝9時の締め切りのまとめが投稿されます。URL を知っている人は誰でもそのチャンネルに投稿できるので、ほかの人に見せないでください。
  関連：G4

### アーカイブ・公開
- **Q：記録を外に公開したい**
  A：2段階あります。「宣伝用に公開」はタイトル・画像・概要・期間・場所だけを公開し、開催前から使えます。「タスクも含めて公開」は開催日を過ぎてから、確認ページで外に出る姿を見たうえで公開します。
  関連：H3・H4

- **Q：公開すると名前が出る？**
  A：メンバーの名前・アバター・チャット・参加時の回答は公開されません。公開されるのは、イベントの基本情報と、公開を選んだタスクの内容と振り返りです。「非公開」にした文字も公開されません。
  関連：H4

- **Q：公開をやめたい**
  A：アーカイブ右上の ⋯ から「公開を停止する」を選びます。外のページから消えるまで数分かかることがあります。
  関連：H5

- **Q：みんなの記録にコメントしたい**
  A：コメントは、メール認証が済んだアカウントでログインすると書けます。いいねはログインしなくても押せます。
  関連：H6

### 引き継ぎ
- **Q：去年のイベントの内容を使いたい**
  言い換え：前年度から引き継ぎたい／コピーしたい
  A：イベントを作るときの最後の質問か、イベント設定の「前の代のイベント」で、前のイベントを登録できます。そのあと「前の代のタスクから追加」で、使いたいタスクを選んで追加します。期日・担当者は引き継がれません。前回の記録はタスクの詳細で読めます。
  関連：I1

### アカウント
- **Q：パスワードを忘れた**
  A：ログイン画面の「パスワードをお忘れですか？」から、メールに届くリンクで新しいパスワードにできます。変えると、ほかの端末はログアウトされます。
  関連：J2

- **Q：確認コードが届かない**
  A：迷惑メールのフォルダを確かめてください。届かなければ、60秒たってから再送できます。メールアドレスを間違えたときは、その画面でアドレスを直せます。
  関連：A2

- **Q：退会したい**
  A：アカウント設定の「アカウントを削除する」から退会できます。元に戻せません。あなたがオーナーのイベントは、ほかにメンバーがいれば別の人に引き継がれ、いなければ削除されます。
  関連：J3

- **Q：ログアウトされた／勝手にようこそ画面になった**
  A：「通信できませんでした」の画面なら、ログアウトされたわけではありません。電波を確かめて「もう一度試す」を押してください。ログインは30日間続きます。
  関連：§7

## 7. トラブルシューティング（切り分けの順）

### 通知が届かない
1. iPhone なら：ホーム画面に追加したアイコンから開いているか（Safari のタブからでは届かない）
2. アプリの中で通知を許可したか（アカウント設定の「通知」）
3. 端末の設定で、ブラウザ（またはイベクリ）の通知が止まっていないか
   - Mac：システム設定 → 通知 → 使っているブラウザ
4. アカウント設定の「テスト通知を送る」で届くか
5. 届かない通知の種類を確かめる：締め切りの通知は担当者だけ、完了の端末通知は管理者だけ
6. それでも届かなければ問い合わせへ

### 画面が真っ白・真っ暗・古いまま
1. アプリ（タブ）を閉じて開き直す
2. ページを読み込み直す（PC は Cmd/Ctrl + Shift + R）
3. 「通信できませんでした」なら電波を確かめて「もう一度試す」
4. 特定の Wi-Fi でだけ開けないときは、Wi-Fi を入り直すかモバイル回線で試す

### 画像・PDF が付けられない
1. 画像5枚・PDF 3つ（10MB）を超えていないか
2. HEIC（iPhone の写真）は、ブラウザによっては読めない → JPEG で保存し直す
3. 1枚ずつ送っている途中で失敗したら、何枚目かが表示される → もう一度試す

### ボタンが見つからない
1. 管理者か（多くのボタンは管理者だけ）
2. スマホか PC か（PC はボトムナビが無く、左端の列）
3. 開催日を過ぎているか（タスクも含めた公開は開催後だけ）

## 8. チャットボットのナレッジの作り

### 8-1. 1件の形

ヘルプのページを、見出し（`##`）ごとに1件に分けます。1件に次のメタ情報を付けます。

```yaml
id: help-c1-invite              # ページの記号＋短い名前。変えない
title: メンバーを招待する
category: メンバー
audience: [管理者]               # 全員 / 管理者 / メンバー / 招待された人 / 誰でも
devices: [all]                   # all / iphone / android / pc
synonyms: [招待URL, 友達を入れる, 参加リンク]
updated: 2026-11-16              # 本体のどの状態に合わせたか
url: https://evecre.pages.dev/help/members/invite
```

- 1件はおおむね 300〜800字。手順が長いページは、手順ごとに分けます。
- §3 の用語集・§6 の Q&A・§12 の数字の表も、それぞれ知識として入れます。

### 8-2. 答え方のルール（システムの指示に入れる）

1. **知識にあることだけを答える。** 知識に無いことは「分からない」と言い、ヘルプのページか問い合わせ先を案内する。機能を推測で作らない。
2. 最初の文で結論を言う。手順は番号つき。最後に関連するヘルプのページのリンクを1つ付ける。
3. 「誰ができるか」が関わる質問では、必ず「管理者だけ」などを添える。
4. 端末で手順が違うときは、相手の端末を聞くか、端末ごとに分けて答える。
5. 用語はアプリの言い方（タスク・管理者・メンバー）を使う。相手が「ミッション」と言っても、タスクのことだと受け取って答える。
6. 次のことは答えずに問い合わせ先へ案内する：
   - アカウントやデータの削除・復元の依頼（チャットボットでは何も操作できない）
   - 個人情報の開示や訂正の請求
   - 障害・不具合の報告（フィードバックのフォームへ）
7. 利用者の名前・メール・イベントの中身を聞かない。チャットボットはアカウントにつながっていないので、イベントの中は見えないと伝える。

### 8-3. 問い合わせ先・フィードバック

- アプリの中の「フィードバックを送る」は Google フォームにつながっています（本体の `components.js`）。チャットボットの「解決しない」の行き先も、ここにそろえるのが簡単です。
- 個人情報の請求は、プライバシーポリシー第10項の連絡先です。

### 8-4. 計測（あとで直すために）

- チャットボットの「答えられなかった質問」を残すと、足りないヘルプのページが分かります（本体で「計測を入れていなかったので、使われていないのか気づかれていないのか判別できなかった」反省がある）。
- 少なくとも：質問の数・答えられなかった数・どのページへのリンクを返したか。
- ★質問の文に個人情報が入ることがあるので、残すなら期間を決め、プライバシーポリシーに書く。

## 9. 書かないこと

| 書かないこと | 理由 |
|---|---|
| 内部の仕組み（CRDT・SSE・API の形・データベース） | 利用者に要らない。変わるたびにヘルプが古くなる |
| セキュリティの仕組みの詳細（CSRF の対策など） | 攻撃の手がかりになる |
| 廃止した機能（メンバーからの提案・リーダーによるチェック・図鑑・アーカイブのいいね） | 「どこにある？」の問い合わせを生む |
| 暫定の機能（既存メンバーにスキルを聞くモーダル） | 回収が済んだら消す予定 |
| 運営の読み取り専用のアカウント（オブザーバー） | ヘルプに書く話ではない。ただし §10-2 を参照 |
| 公開 API の使い方 | 外部サイト自身が使うためのもの |

## 10. ヘルプを出す前にそろえたいもの

### 10-1. 規約・ポリシー（2026-11-16 に v1.1 へ改定済み）
- 「ミッション」を「タスク」に改めました。
- 公開ページ「みんなの記録」（公開の範囲・コメント・いいねの Cookie）、Discord・Slack との連携、PDF の保存、引き継ぎを追記しました。
- ヘルプとチャットボットの「公開されるもの・されないもの」「Discord・Slack に送るもの」は、プライバシーポリシーの第4-2項・第5項と同じ言い方にそろえてください。

### 10-2. 運営者がイベントの中身を見ることについて
- 本番では運営者がイベントの中身を見ることはありません（読み取り専用の仕組みはテストユーザー向けのみ）。ヘルプ・チャットボットでも触れません（2026-11-16 決定）。

### 10-3. 実機でまだ確かめていない挙動
本体の CLAUDE.md で「未確認」とされているもの。ヘルプで断言しないでください：
- Safari でのファイルのドラッグ＆ドロップ
- 端末の「戻る」（iPhone のスワイプ・Android の戻るボタン）
- 端末を変えたときの案内の既読（端末ごとに記録しているので、別の端末ではもう一度出る）

### 10-4. 決めてほしいこと
- 問い合わせの窓口（フォームだけか、メールもか）
- ヘルプの URL の形（例：`/help/<カテゴリ>/<ページ>`）
